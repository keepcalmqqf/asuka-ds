# Asuka DS M1–M3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a shadcn-style, source-owned Design System prototype for Asuka through milestones M1, M2 and M3.

**Architecture:** Strongly typed theme tokens drive `ui.StyleFunc`; `Pressable` and `Field` centralize interactive and form semantics; surface components are drawn while controls and overlays wrap platform-native primitives.

**Tech Stack:** Go 1.26+, Asuka `v0.1.1`, `signal`, `ui`, `uitest`, `asuka vet`.

**Spec:** `DESIGN.md`

## Global Constraints

- Asuka `v0.1.1`; Go `1.26+`.
- Components run once; changing values read through `signal.Accessor`, `ui.StyleFunc`, `ui.Show`, `ui.Dynamic` or `ui.For`.
- `View` has no native `Disabled`/`Selected`/`Expanded`; use `Pressable` conventions and document the `Hint` fallback.
- Native controls keep their own chrome; `TextField{Plain:true}` is the one input exception.
- `ui.Sheet` children do not render; `Overlay` must build sheet content through `Content`.
- Theme is an app-level signal; no per-subtree custom theme context.
- All colors, radii, type and motion durations come from `Theme`.

## Review Focus

- A dynamic `signal.Accessor[bool]` disables a `Pressable` after mount: its hint becomes `Unavailable`, its action stops firing, and its style dims.
- A `Command` query narrows results below the current selected index: exactly one visible row remains selected.
- A disabled `Select` exposes no platform menu and does not change its selection.
- An `Input` with both description and error shows both, with one accessible group name and a header-role label.
- `Overlay` in sheet mode renders `Content` after `Open` changes; `Popover` keeps its anchor children visible.
